MISSION

Je veux concevoir une application web premium de playlist musicale collaborative pour événements, dont le premier univers est le mariage.

Le produit ne doit PAS être conçu comme une simple playlist.

L’idée centrale est :

Composer, organiser, partager et vivre la bande-son complète d’un événement dans le temps.

L’application doit permettre de rechercher des morceaux, les prévisualiser, les organiser, créer des playlists et dossiers, construire les enchaînements, collaborer avec d’autres personnes et placer toute la musique sur une Timeline de la journée et de la nuit.

Le résultat doit donner l’impression d’un produit musical premium de nouvelle génération.

⸻

DIRECTION VISUELLE — OBJECTIF ABSOLU

Je veux une interface qui combine :

* la simplicité immédiate et addictive des grandes applications de streaming ;
* le niveau de finition, de fluidité et de sophistication d’un produit Apple haut de gamme ;
* une identité visuelle propre et originale.

⚠️ Ne pas copier Spotify ou Apple Music.

Il faut s’inspirer de leurs qualités ergonomiques et de leur niveau de finition, mais créer une interface originale.

Je veux quelque chose qui donne immédiatement cette impression :

« C’est familier, je comprends instantanément comment l’utiliser, mais je n’ai jamais vu exactement cette interface auparavant. »

Le produit doit être plus ambitieux visuellement qu’une application de streaming classique.

⸻

STYLE VISUEL

Ambiance générale

Créer une interface :

* premium ;
* immersive ;
* musicale ;
* éditoriale ;
* très fluide ;
* extrêmement soignée ;
* moderne mais durable.

Pas une interface SaaS.

Pas un dashboard administratif.

Pas une accumulation de cartes.

Pas de design générique généré par IA.

⸻

Couleurs

Utiliser une base :

* noir profond ;
* anthracite ;
* blanc cassé ;
* gris subtil ;
* couleurs dynamiques extraites automatiquement des pochettes musicales.

Les pochettes doivent influencer subtilement l’environnement visuel.

Par exemple :

Lorsqu’un morceau est sélectionné, une lumière ou un gradient très diffus peut reprendre certaines couleurs dominantes de sa pochette.

Cela doit rester :

* élégant ;
* subtil ;
* cinématographique.

Pas de dégradés criards.

Pas d’effet gaming.

⸻

CONCEPT PRINCIPAL : MUSIC OS FOR EVENTS

L’application est organisée autour de cinq espaces principaux.

1 — DISCOVER / RECHERCHER

Un espace de recherche musicale extrêmement rapide.

En haut :

🔍 Rechercher un morceau, un artiste ou une ambiance

La recherche doit accepter :

* nom d’artiste ;
* titre ;
* album ;
* genre ;
* décennie ;
* ambiance ;
* moment du mariage.

Exemples :

* Earth Wind and Fire
* chanson entrée des mariés
* funk années 80
* cocktail chic
* musique universelle pour danser
* slow romantique
* fin de soirée

Les résultats doivent afficher :

* grande ou moyenne pochette ;
* titre ;
* artiste ;
* durée ;
* année ;
* genre ;
* BPM ;
* tonalité ;
* niveau d’énergie.

Chaque morceau doit pouvoir être :

* prévisualisé ;
* ajouté ;
* placé dans un dossier ;
* envoyé dans une playlist ;
* placé dans la Timeline.

⸻

2 — BIBLIOTHÈQUE MUSICALE

Créer une bibliothèque immédiatement utilisable.

Elle ne doit pas être vide.

Prévoir une première collection éditoriale :

💍 Mariage Universel

avec des catégories :

* Cérémonie
* Accueil invités
* Cocktail
* Dîner
* Entrée des mariés
* Moments émotionnels
* Ouverture de bal
* Dancefloor
* Classiques intergénérationnels
* Fin de soirée

L’objectif est que l’utilisateur puisse immédiatement explorer une immense culture musicale adaptée aux événements.

Prévoir également la possibilité de créer :

* playlists ;
* dossiers ;
* collections ;
* sets DJ ;
* moments Timeline.

⸻

3 — PLAYLIST BUILDER

Créer une expérience de création de playlist beaucoup plus visuelle qu’une simple liste.

Chaque morceau est représenté avec :

* miniature de la pochette ;
* titre ;
* artiste ;
* durée ;
* BPM ;
* énergie.

Les morceaux peuvent être :

* déplacés par drag and drop ;
* regroupés ;
* verrouillés ;
* marqués comme essentiels ;
* exclus ;
* proposés à la collaboration.

Créer une visualisation facultative de l’énergie de la playlist.

Par exemple :

LOW ENERGY
↓
progression
↓
HIGH ENERGY

L’utilisateur doit immédiatement comprendre la dynamique de son set.

⸻

4 — DJ MODE

Créer une interface immersive permettant de visualiser l’enchaînement entre les morceaux.

L’écran doit afficher :

NOW PLAYING

Grande pochette centrale.

Autour :

* morceau précédent ;
* morceau suivant ;
* BPM ;
* tonalité ;
* énergie.

Ajouter une représentation graphique de la progression audio.

Ne pas nécessairement développer immédiatement un véritable moteur DJ professionnel.

Pour la première version, construire l’expérience et l’interface.

Prévoir l’architecture pour :

* crossfade ;
* transition ;
* beat matching ;
* fade in ;
* fade out ;
* cut ;
* transition automatique.

⸻

TRANSITION INTELLIGENCE

Entre deux morceaux, afficher une carte intelligente.

Exemple :

Compatibility

September
↓
Uptown Funk

94 %

✓ énergie compatible
✓ BPM proche

🔥 Explosion

🌊 Transition fluide

🎭 Contraste

L’intelligence artificielle propose.

L’humain décide.

⸻

Chaque moment peut contenir :

* une musique signature ;
* une durée ;
* un niveau d’énergie.

⸻

LA TIMELINE DOIT ÊTRE UNE EXPÉRIENCE VISUELLE

Je ne veux pas une liste d’agenda.

Je veux une véritable colonne vertébrale narrative.

La Timeline doit permettre de voir :

* le temps ;
* le moment ;
* la musique ;
* l’énergie.

Les pochettes musicales doivent apparaître directement dans la Timeline.

Au survol d’un morceau :

* agrandissement subtil ;
* aperçu du morceau ;
* actions rapides ;
* informations ;
* possibilité de lecture.

La Timeline doit donner l’impression de regarder la bande-son complète d’une journée.

⸻

COLLABORATION

Permettre aux mariés ou organisateurs de partager une playlist.

Créer un mode invité très simple.

L’invité arrive et voit :

🎵 Quel morceau voulez-vous offrir à cette histoire ?

Un champ de recherche.

Il peut :

* rechercher un morceau ;
* écouter un extrait ;
* proposer ;
* écrire un message expliquant son choix.

Exemple :

« Cette chanson nous rappelle nos vacances ensemble. »

Chaque morceau proposé peut donc posséder :

* une musique ;
* un auteur de proposition ;
* une histoire ;
* un vote ;
* un statut.

Statuts :

* proposé ;
* validé ;
* refusé ;
* à discuter.

⸻

INNOVATION — MUSIC MEMORY

Prévoir une fonctionnalité fondamentale :

La musique devient l’index des souvenirs.

Après l’événement, un morceau peut être associé à :

* photos ;
* vidéos ;
* messages ;
* souvenirs.

Exemple :

23:42

🎵 Dancing Queen

Voir :

* photos prises pendant ce morceau ;
* vidéos ;
* messages des invités.

L’utilisateur doit pouvoir naviguer :

Timeline → Musique → Souvenirs

ou :

Musique → Moment → Souvenirs

LECTEUR MUSICAL GLOBAL

Créer un lecteur persistant.

Il reste accessible quelle que soit la page.

Il doit être extrêmement élégant.

Contenir :

* miniature de la pochette ;
* titre ;
* artiste ;
* play/pause ;
* précédent ;
* suivant ;
* progression.

Le lecteur ne doit jamais casser la navigation.

Lorsqu’un morceau joue, l’application reste vivante mais discrète.

GESTES ET INTERACTIONS

Priorité absolue aux interactions.

Je veux :

* drag and drop fluide ;
* transitions naturelles ;
* hover subtil ;
* animations courtes ;
* agrandissements progressifs ;
* feedback immédiat.

Ne jamais utiliser d’animations décoratives inutiles.

Chaque animation doit expliquer une action ou renforcer la sensation de manipulation musicale.

Timeline

Collaborer

Puis l’espace principal.

DESIGN DES POCHETTES

Les pochettes sont essentielles.

Elles doivent constituer une grande partie de l’identité visuelle.

Créer :

* grandes pochettes éditoriales ;
* grilles musicales ;
* listes compactes ;
* pochettes empilées ;
* animations au hover.

Les pochettes ne doivent jamais être enfermées dans de grosses cartes SaaS.

La musique doit respirer.

Avec des données de démonstration structurées pour montrer :

* extraits simulés ou intégrables via une source autorisée ;
* playlists ;
* dossiers ;

IMPORTANT — ARCHITECTURE

Ne pas enfermer le projet dans des données fictives impossibles à remplacer.

Créer une architecture où les sources musicales pourront être connectées ultérieurement.

Séparer clairement :

1. UI
2. données musicales
3. service de recherche
4. service de prévisualisation
5. bibliothèque utilisateur
6. collaboration
7. Timeline
8. moteur de recommandations / compatibilité

Prévoir des interfaces et services remplaçables.

⸻

IMPORTANT — DROITS ET MUSIQUE

Pour cette première version :

Ne pas construire un système illégal de téléchargement ou de redistribution de fichiers musicaux.

Construire l’expérience produit autour de :

* recherche ;
* métadonnées ;
* prévisualisation via sources autorisées ;
* organisation ;
* achat ou acquisition future via plateformes compatibles ;
* import de fichiers légalement détenus par l’utilisateur lorsque cela sera applicable.

Le système doit pouvoir évoluer ultérieurement vers des intégrations officielles avec des plateformes musicales et des mécanismes d’acquisition ou de lecture autorisés.

⸻

PRIORITÉ FINALE

Avant d’ajouter de nombreuses fonctionnalités secondaires, je veux que tu perfectionnes l’expérience principale :

Je recherche un morceau → je l’écoute → je l’ajoute → je le place dans la Timeline → je construis son enchaînement → je partage la sélection.

Cette boucle doit être exceptionnelle.

L’utilisateur doit avoir envie de manipuler la musique pendant des heures.

⸻

À la fin, je dois pouvoir ouvrir l’application et comprendre immédiatement :

1. comment rechercher une musique ;
2. comment l’écouter ;
3. comment l’ajouter ;
4. comment créer une playlist ;
5. comment créer des dossiers ;
6. comment déplacer les morceaux ;
7. comment construire la Timeline ;
8. comment visualiser l’énergie ;
9. comment simuler les enchaînements ;
10. comment partager la playlist avec d’autres personnes.

Le résultat final doit ressembler à la naissance d’une nouvelle catégorie de produit :

THE SOUNDTRACK OF AN EVENT

Une journée ne se raconte pas seulement avec des images. Elle possède aussi sa bande-son.

Ne fais pas une simple copie d’une application de streaming.

Conçois une expérience musicale nouvelle, premium, immersive et immédiatement compréhensible.

Commence par analyser la meilleure architecture de l’interface, puis construis le prototype progressivement en privilégiant la qualité de l’expérience principale plutôt que la quantité de fonctionnalités.
